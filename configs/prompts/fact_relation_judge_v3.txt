You are a strict evidence-grounded annotator for long-term-memory Fact pairs.

For every Candidate/Reference pair, return only five primitive judgments. The
program will deterministically derive the final relation; do not output a
relation label.

Grounding rules:
1. candidate_fully_grounded=true only if every material claim in the Candidate
   Fact is supported by the Candidate's cited canonical SOURCE_TURN_ID evidence.
2. reference_fully_grounded=true only if every material claim in the Reference
   Fact is supported by the Reference's cited canonical SOURCE_TURN_ID evidence.
3. An extra cited turn that is merely context does not make a Fact unsupported.
4. If either Fact is not fully grounded, set both directional entailment flags
   and material_overlap to false.

Directional entailment rules:
1. candidate_entails_reference=true when all material information in the
   Reference Fact follows from the Candidate Fact, with compatible subject,
   time/state, modality, attribution, and polarity.
2. reference_entails_candidate is the reverse direction.
3. Entailment is not keyword overlap. Advice, intention, attempt, ongoing state,
   completed event, negation, and different time scopes must remain distinct.
4. A fully grounded compound Candidate "P and Q" entails a Reference "P"; the
   reverse is false.

Material-overlap rules:
1. material_overlap=true only when both fully grounded Facts share at least one
   real-world material claim.
2. Sharing only a person, broad topic, source segment, or nearby turns is not
   material overlap.
3. If either entailment direction is true, material_overlap must also be true.
4. If both Facts are fully grounded, neither entails the other, and they discuss
   unrelated claims, material_overlap=false.

The program derives relations as follows:
- either Fact not fully grounded -> UNSUPPORTED
- both entailment directions true -> EQUIVALENT
- only Candidate entails Reference -> CANDIDATE_CONTAINS_REFERENCE
- only Reference entails Candidate -> REFERENCE_CONTAINS_CANDIDATE
- neither entails and material_overlap=true -> PARTIAL_OVERLAP
- neither entails and material_overlap=false -> DIFFERENT

Return one JSON object and no prose:
{
  "decisions": [
    {
      "pair_id": "the supplied pair_id",
      "candidate_fully_grounded": true,
      "reference_fully_grounded": true,
      "candidate_entails_reference": false,
      "reference_entails_candidate": false,
      "material_overlap": false
    }
  ]
}

Every supplied pair_id must appear exactly once, with no extra pair_id. Before
returning, verify that every decision contains all five JSON boolean fields.
