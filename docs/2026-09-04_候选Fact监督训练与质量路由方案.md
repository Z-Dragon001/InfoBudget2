# 候选 Fact 监督训练与质量路由方案

- 日期：2026-09-04
- 项目：InfoBudget2
- 阶段：候选 Fact 与参考 Fact 已生成，准备构造监督标签并训练质量路由器

## 一、结论

当前不需要再训练一个负责生成 Fact 的小语言模型。推荐的下一步是：

> 使用 small、medium、large 三个模型已经生成的候选 Fact，与 GPT-5.6 生成的参考 Fact 构造监督标签；随后训练一个“冻结文本编码器 + MLP”的质量评分器，预测每个候选模型处理当前主题段时可能获得的 Fact-F1，最后根据预测质量和成本选择实际调用的模型。

这里所说的“小模型”是文本编码器，而不是一个新的生成式 LLM。

推荐学习的目标不是：

```text
主题段 → small / medium / large 类别
```

而是：

\[
(x_d,c_m)\rightarrow \hat q_{d,m}
\]

其中：

- \(x_d\)：主题段原文及结构特征；
- \(c_m\)：候选模型的冻结能力表示；
- \(\hat q_{d,m}\)：模型 \(m\) 在主题段 \(d\) 上预计能够获得的 Fact-F1。

同一个主题段分别与三个候选模型的能力表示组合：

```text
(segment, small_profile)  → predicted Fact-F1
(segment, medium_profile) → predicted Fact-F1
(segment, large_profile)  → predicted Fact-F1
```

得到三个连续质量预测后，再通过确定性的成本—质量决策规则选择模型。

这种方法相较直接训练三分类器具有以下优点：

- 保留模型之间的连续质量差距；
- 可以灵活调整成本与质量的权衡；
- 改变预算或容忍阈值时不需要重新训练；
- 可以扩展到新的候选模型；
- 可以输出可解释的模型质量预测。

## 二、GPT-5.6 参考 Fact 的质量控制

如果所谓 Gold Fact 完全由 GPT-5.6 自动生成、没有经过人工确认，在论文和实验报告中最好称为：

- Reference Fact；
- Silver Reference；
- LLM-generated Gold；
- Silver-Gold Fact。

不应未经验证就把它描述为绝对正确的人工 Gold。

每个参考 Fact 至少应具备以下字段：

```json
{
  "reference_fact_id": "r1",
  "text": "Alice moved to Beijing in 2023.",
  "source_turn_ids": [12],
  "verification_status": "source_grounded"
}
```

需要完成以下质量检查。

### 2.1 来源支撑

每个参考 Fact 必须能从对应的原始对话或主题段中推出，并保存有效的 `source_turn_ids`。

### 2.2 原子性

一个 Fact 尽量只表达一个事件、属性或状态。如果一条 Fact 同时表达多个可以独立判断真假的信息，应拆分为多个原子 Fact。

### 2.3 去重

语义相同但表述不同的参考 Fact 应合并，否则候选模型可能因为没有重复输出而被错误计算为漏召回。

### 2.4 时间和状态一致性

如果对话中存在状态更新，应明确区分：

- 当前有效状态；
- 已失效的旧状态；
- 仍然需要保留的历史事件；
- 否定、撤销和纠正信息。

### 2.5 人工抽样审计

建议对 5%～10% 的样本进行分层人工审计，重点覆盖：

- 多人物绑定；
- 时间更新；
- 否定与撤销；
- 指代消解；
- 跨句信息组合；
- GPT-5.6 是否遗漏原文中的事实。

不建议让同一个 GPT-5.6 同时生成全部 Reference Fact、判断全部候选匹配，并且完全不做人工抽检，否则可能产生同源评价偏差。

## 三、将候选 Fact 转换为监督标签

设主题段 \(d\) 的参考 Fact 集合为：

\[
G_d=\{g_1,g_2,\ldots,g_K\}
\]

模型 \(m\) 生成的候选 Fact 集合为：

\[
F_{d,m}=\{f_1,f_2,\ldots,f_N\}
\]

### 3.1 候选 Fact 与参考 Fact 对齐

不能只使用字符串完全相等，因为语义等价的 Fact 可能具有不同表述。例如：

```text
Alice moved to Beijing in 2023.
Alice relocated to Beijing during 2023.
```

推荐使用两阶段匹配流程：

```text
候选 Fact 与参考 Fact
    ↓
Embedding 相似度召回候选匹配对
    ↓
固定 Judge 判断是否语义等价
    ↓
检查 source_turn_ids 是否存在有效来源交集
    ↓
执行一对一最大二分图匹配
```

Judge 决策建议保存为：

```json
{
  "candidate_fact_id": "c1",
  "reference_fact_id": "r3",
  "equivalent": true,
  "source_supported": true,
  "confidence": 0.94,
  "reason_code": "semantic_paraphrase"
}
```

必须使用一对一匹配，否则一个参考 Fact 可能被多个重复候选 Fact 同时计算为 TP。

### 3.2 TP、FP、FN 定义

- TP：与某个参考 Fact 语义等价、来源有效，并且未被重复匹配的候选 Fact；
- FP：幻觉、重复、来源错误、人物绑定错误或无法匹配的候选 Fact；
- FN：参考集合中未被候选模型提取出来的 Fact。

由此计算：

\[
Precision=\frac{TP}{TP+FP}
\]

\[
Recall=\frac{TP}{TP+FN}
\]

\[
FactF1=\frac{2TP}{2TP+FP+FN}
\]

最终每个主题段产生三条监督记录：

```json
{
  "segment_id": "seg_001",
  "model_id": "small",
  "precision": 0.75,
  "recall": 0.60,
  "silver_strict_fact_f1": 0.6667
}
```

```json
{
  "segment_id": "seg_001",
  "model_id": "medium",
  "precision": 0.80,
  "recall": 0.80,
  "silver_strict_fact_f1": 0.80
}
```

```json
{
  "segment_id": "seg_001",
  "model_id": "large",
  "precision": 0.85,
  "recall": 0.90,
  "silver_strict_fact_f1": 0.874
}
```

需要在实验协议中提前冻结空集合情况的计算定义：

| Reference Fact | Candidate Fact | 推荐 Fact-F1 |
|---|---|---:|
| 空 | 空 | 1 |
| 非空 | 空 | 0 |
| 空 | 非空 | 0 |

当前项目已经实现了来源约束的一对一匹配和 Fact-F1 构造：

- `infobudget/quality_router/labeling.py`
- `scripts/build_fact_quality_labels.py`

正式论文标签应提供冻结的 Judge 匹配结果；字符串完全匹配模式只适合作为管线测试基线。

## 四、是否需要“小模型 + MLP”

需要一个文本表示模型，但不需要增加新的生成式小模型。

推荐结构如下：

```text
主题段文本
  ↓
冻结的小型文本编码器
  ↓
384 维文本 embedding
  ├── 6 维主题段结构特征
  └── 7 维候选模型能力向量
  ↓
拼接为 397 维输入
  ↓
MLP：397 → 512 → 128 → 1
  ↓
Sigmoid
  ↓
预测 Fact-F1 ∈ [0,1]
```

### 4.1 文本编码器

当前工程使用：

```text
sentence-transformers/all-MiniLM-L6-v2
embedding dimension = 384
```

第一版应冻结文本编码器，只训练 MLP。这样可以降低显存需求、提高训练稳定性，并减少小数据条件下的过拟合。

可以根据独立主题段数量采用以下经验配置：

- 少于 2,000 个独立主题段：冻结编码器，MLP 使用 `256 → 64`；
- 2,000～20,000 个主题段：冻结编码器，使用 `512 → 128`；
- 超过 20,000 个主题段：可以比较冻结编码器与只微调最后若干层；
- 无论有多少 `(segment, model)` 记录，独立样本量主要取决于 segment 数量，不能简单乘以 3。

如果数据主要是中文或中英混合，需要先比较一个多语言文本编码器。编码器一旦选定，就应在正式实验前冻结模型名、revision、最大长度和长文本聚合策略。

### 4.2 主题段结构特征

第一版可以沿用当前项目的 6 维结构特征，例如：

\[
g_d=[
token\_count,
turn\_count,
character\_count,
line\_count,
number\_count,
unique\_token\_count
]
\]

后续可以扩展：

- 实体数量和实体密度；
- 人物数量；
- 时间表达数量；
- 否定信号；
- 状态更新或冲突信号；
- 指代密度；
- 跨句依赖强度。

第一版建议保持当前 6 维定义，避免特征工程引入额外变量。

### 4.3 模型能力表示

推荐使用冻结的 7 维 MemoryPrint：

\[
c_m=[
memory\_recall,
target\_memory\_precision,
memory\_accuracy,
current\_state\_accuracy,
target\_binding\_accuracy,
stale\_value\_rejection,
evidence\_f1
]
\]

模型 ID 可以保存用于审计，但不建议直接作为可学习的 one-hot 输入。

需要注意：如果只有 small、medium、large 三个模型，能力向量实际上只有三个取值。此时实验可以证明固定三模型池上的有效性，但不能有力声称对任意新模型都能泛化。

若论文重点是新模型泛化，需要：

- 增加更多候选模型；
- 尽量覆盖多个模型家族；
- 进行 leave-one-model-out；
- 进行 leave-one-family-out。

## 五、共享 MLP 与三输出 MLP 的选择

存在两种合理设计：

| 使用目标 | 推荐结构 |
|---|---|
| 永远只使用固定的 small、medium、large | 一个 MLP 直接输出三个质量值 |
| 希望增减候选模型或接入新模型 | 共享的 `(segment, model_profile) → quality` MLP |

InfoBudget2 更适合第二种设计：

\[
\hat q_{d,m}
=
\sigma\left(
MLP([h_d;g_d;c_m])
\right)
\]

同一个 MLP 对所有候选模型共享参数。

不过，建议将“三输出 MLP”加入实验基线。它可能在固定三模型池上表现更好，但不能自然接入第四个模型。

当前共享标量模型和配置位于：

- `infobudget/quality_router/model.py`
- `configs/quality_router.yaml`

## 六、训练损失设计

### 6.1 最小可行版本

第一版先使用绝对质量回归：

\[
\mathcal L_{abs}
=
\frac{1}{N}
\sum_{d,m}
Huber(\hat q_{d,m},q_{d,m})
\]

Huber Loss 相比 MSE 不容易被少量异常标签带偏，更适合 GPT 参考事实和 Judge 匹配可能存在噪声的情况。

当前项目的默认设置为：

- 优化器：AdamW；
- 学习率：\(3\times10^{-4}\)；
- weight decay：0.01；
- batch size：128；
- Huber delta：0.1；
- 最大训练轮数：100；
- early stopping patience：10；
- 使用验证集 MAE 选择 checkpoint。

### 6.2 论文增强版本

路由真正关心的不只是绝对质量，还包括三个模型之间的质量差距。可以增加差距损失：

\[
\mathcal L_{gap}
=
Huber\left(
(\hat q_{d,a}-\hat q_{d,b}),
(q_{d,a}-q_{d,b})
\right)
\]

再加入排序损失：

\[
\mathcal L_{rank}
=
BCE\left(
\sigma\left(
\frac{\hat q_{d,a}-\hat q_{d,b}}{\tau}
\right),
\mathbb 1[q_{d,a}>q_{d,b}]
\right)
\]

对于真实质量差距很小的模型对，例如：

\[
|q_{d,a}-q_{d,b}|<0.02
\]

可以标记为 tie，不计算排序损失，避免把标签噪声学习成确定排序。

推荐的初始组合为：

\[
\boxed{
\mathcal L
=
1.0\mathcal L_{abs}
+
0.25\mathcal L_{gap}
+
0.10\mathcal L_{rank}
}
\]

这些权重只能在验证集上调整。

如果使用 pairwise loss，训练 batch 最好按照完整 triplet 采样：

```text
一个训练单元 =
(segment, small) +
(segment, medium) +
(segment, large)
```

否则同一主题段对应的三个模型可能不在同一个 batch 中，不便于计算差距和排序损失。

## 七、数据划分与泄漏控制

必须首先按照 conversation 或 sample 划分：

```text
conversation/sample
├── train
├── validation
└── test
```

然后在每个集合内部展开：

```text
segment × small
segment × medium
segment × large
```

严禁将全部 `(segment, model)` 记录混合后随机划分，否则可能出现：

```text
seg_001 + small 进入训练集
seg_001 + medium 进入验证集
seg_001 + large 进入测试集
```

这会造成严重信息泄漏。

推荐划分方式：

- 70% train；
- 15% validation；
- 15% test；
- 或采用按 conversation 分组的 5-fold cross-validation。

能力探针数据也必须独立于 train、validation 和 test，尤其不能使用测试集计算模型 MemoryPrint。

## 八、模型选择与部署规则

对于一个新主题段，质量评分器分别输出：

\[
[\hat q_s,\hat q_m,\hat q_l]
\]

不建议简单选择预测质量最大的模型，因为这样通常会频繁调用大模型。推荐使用 \(\varepsilon\)-非劣规则。

首先计算预测最优质量：

\[
q_{max}=\max_m\hat q_{d,m}
\]

定义可接受模型集合：

\[
\mathcal A_d=
\{m:q_{max}-\hat q_{d,m}\le\varepsilon\}
\]

然后选择集合中成本最低的模型：

\[
\boxed{
m^*(d)
=
\arg\min_{m\in\mathcal A_d}cost(m)
}
\]

例如：

```text
small  = 0.72
medium = 0.76
large  = 0.78
```

如果 \(\varepsilon=0.05\)，三个模型都在最优质量的 0.05 范围内，因此选择成本最低的 small。

如果预测为：

```text
small  = 0.55
medium = 0.70
large  = 0.82
```

则只有 large 满足质量条件，因此选择 large。

价格不应作为质量 MLP 的输入。MLP 只预测质量，价格只在最终决策层使用。这样即使模型价格发生变化，也不需要重新训练质量评分器。

## 九、安全机制

### 9.1 最低质量门槛

如果预测为：

```text
small  = 0.20
medium = 0.22
large  = 0.24
```

三个模型虽然非常接近，但并不代表 small 足够可靠。

建议增加最低质量门槛：

\[
q_{floor}=0.30
\]

实际数值应由验证集确定。如果：

\[
\max_m\hat q_{d,m}<q_{floor}
\]

则应：

- 选择预测质量最高的候选模型；
- 或触发更强模型或人工回退；
- 将该样本标记为 `low_quality_fallback`。

### 9.2 预测不确定性

可以在验证集上计算真实质量差距与预测差距之间的残差，并使用 90% 或 95% 分位数构造保守上界：

\[
g^{upper}_{d,m}
=
\hat g_{d,m}+r_{0.95}
\]

只有满足：

\[
g^{upper}_{d,m}\le\varepsilon
\]

才允许降级到便宜模型。

第一版使用验证残差分位数即可，不需要立即引入 Deep Ensemble 或 MC Dropout。

## 十、评估方案

不能只报告质量 MLP 的 MAE，还必须评估最终路由表现。

### 10.1 质量预测指标

- MAE；
- RMSE；
- Spearman 相关系数；
- small、medium、large 的 pairwise 排序准确率；
- 预测质量差距 MAE；
- 分模型、分数据集、分主题段难度的误差。

### 10.2 路由指标

- 路由后的真实平均 Fact-F1；
- 相对真实最优模型的 regret；
- Mean、P90 和 P95 Regret；
- `Regret > 0.05` 的质量违反率；
- small、medium、large 的选择比例；
- 相对 All-large 的成本节省率；
- 与真实质量 Oracle 路由的一致率。

单个主题段的 regret 定义为：

\[
Regret_d
=
\max_mq_{d,m}-q_{d,m^*(d)}
\]

成本节省率可以定义为：

\[
CostSaving
=
1-
\frac{\sum_d cost(m^*(d))}
{\sum_d cost(large)}
\]

### 10.3 必要基线

至少比较：

1. All-small；
2. All-medium；
3. All-large；
4. Random；
5. 三分类 MLP；
6. 共享质量 MLP；
7. 共享质量 MLP + pairwise loss；
8. \(\varepsilon=0\) 的预测最优模型；
9. 不确定性感知 \(\varepsilon\)-路由；
10. 使用真实 Fact-F1 的 Oracle 路由。

### 10.4 消融实验

- 去掉 MemoryPrint；
- 去掉主题段 embedding；
- 去掉结构特征；
- 只使用模型 one-hot；
- 比较标量共享 MLP 与三输出 MLP；
- 比较有无 gap loss；
- 比较有无 ranking loss；
- 比较不同 \(\varepsilon\)；
- 比较有无 `quality_floor`；
- leave-one-model-out；
- leave-one-family-out。

## 十一、是否需要微调小型 Fact 提取模型

当前阶段不建议微调新的小型 Fact 提取模型。

当前研究目标是学习“哪个已有模型适合哪个主题段”，不是重新训练提取器。

如果以后需要将 GPT-5.6 Reference Fact 蒸馏给一个小模型，可以单独构造：

```text
输入：主题段原文
输出：结构化 Reference Fact JSON
```

但是一旦小模型经过监督微调：

- 候选 Fact 分布会变化；
- Fact-F1 标签会变化；
- 模型 MemoryPrint 会变化；
- 原质量评分器和路由结果可能失效。

因此推荐顺序是：

```text
先完成现有 small/medium/large 的路由实验
    ↓
固定并评估主实验结果
    ↓
再将 SFT 小模型作为新的候选模型
    ↓
重新生成候选 Fact、能力画像和监督标签
    ↓
重新校准或训练质量路由器
```

不要在当前质量路由器训练过程中同时修改候选提取模型。

## 十二、完整实施顺序

### 阶段 1：整理 Reference Fact

- 完成来源验证；
- 完成原子化；
- 完成语义去重；
- 检查人物绑定；
- 检查时间与状态更新；
- 进行分层人工抽样审计。

输出：

```text
reference_facts.jsonl
```

### 阶段 2：生成候选—参考匹配

- 使用语义检索召回潜在匹配对；
- 使用冻结 Judge 判断语义等价；
- 检查来源约束；
- 执行一对一最大匹配；
- 保存 Judge 版本、Prompt hash 和决策结果。

输出：

```text
judge_decisions.jsonl
fact_matches.jsonl
```

### 阶段 3：生成监督标签

- 计算每个 `(segment, model)` 的 TP、FP 和 FN；
- 计算 Precision、Recall 和 Strict Fact-F1；
- 保存参考集合 hash 和候选提取 run ID。

输出：

```text
fact_quality_labels.jsonl
```

### 阶段 4：准备模型能力画像

- small、medium、large 在相同独立探针集上运行；
- 计算冻结的 7 维 MemoryPrint；
- 保存 benchmark hash、代码 commit 和 profile ID。

输出：

```text
model_capability_profiles.json
```

### 阶段 5：训练最小可行质量评分器

- 冻结文本编码器；
- 构造 397 维输入；
- 使用 `397 → 512 → 128 → 1` MLP；
- 使用 Huber Loss；
- 使用验证集 MAE 早停；
- 保存 scaler、embedding revision 和数据 hash。

输出：

```text
quality_scorer.pt
training_metrics.json
validation_predictions.jsonl
```

### 阶段 6：增强模型间差距学习

- 增加 gap loss；
- 增加 ranking loss；
- 使用 segment triplet batch；
- 与纯 Huber 模型进行受控比较。

### 阶段 7：验证集校准

- 扫描 \(\varepsilon\)；
- 校准预测差距残差；
- 选择 `quality_floor`；
- 冻结 OOD 和低质量回退规则；
- 冻结成本快照和 tie-break 规则。

### 阶段 8：测试集评估

- 测试集不再调整模型或阈值；
- 报告 Fact-F1、regret、成本和模型选择比例；
- 报告与 All-large 和 Oracle 的差距；
- 可选进行下游 QA 外部验证。

## 十三、训练与部署阶段的关键区别

训练阶段需要让三个候选模型都处理相同主题段，因为需要计算监督标签：

```text
segment
├── small candidate facts
├── medium candidate facts
└── large candidate facts
```

部署阶段不能继续让三个模型全部提取，否则无法节省生成成本。部署时应当：

```text
新主题段
    ↓
轻量文本编码器 + 结构特征
    ↓
共享质量 MLP 预测三个模型的质量
    ↓
成本—质量决策
    ↓
只调用最终选中的一个提取模型
```

因此，候选 Fact 在当前阶段主要用于产生训练标签，而不应作为预提取路由器的线上输入。

如果将三个模型已经生成的候选 Fact 作为路由输入，则会变成“生成后的候选选择器”，它可能提高最终质量，但无法节省三个候选模型的生成费用。

## 十五、最终建议

当前最优先的工作不是增加新的 LLM，而是：

1. 冻结 GPT-5.6 Reference Fact；
2. 完成 `candidate fact ↔ reference fact` 的语义等价 Judge 决策；
3. 生成可靠的 `fact_quality_labels.jsonl`；
4. 生成或确认三个候选模型的 MemoryPrint；
5. 先训练现有的共享质量 MLP；
6. 在验证集上校准 \(\varepsilon\)、质量门槛和不确定性边界；
7. 最后在完全隔离的测试集上评估 Fact 质量、路由 regret 和真实成本。

主模型可以表述为：

\[
\boxed{
\hat q_{d,m}
=
f_\theta(x_d,c_m)
}
\]

最终路由规则可以表述为：

\[
\boxed{
m^*(d)
=
\arg\min_m cost(m)
\quad
\text{s.t.}
\quad
\max_k\hat q_{d,k}-\hat q_{d,m}\le\varepsilon
}
\]

整个方案的核心研究结果应围绕：

\[
\boxed{
\text{Fact 质量}
\;--\;
\text{模型调用成本}
\;--\;
\text{路由 Regret}
}
\]

展开，而不是只报告 MLP 的回归误差或最终模型分类准确率。
